### 1.3. Исправления по результатам аудита

1. **Сериализация мутаций раунда** — `bet` / `cashout` / `tick` в одной очереди `runExclusive`, чтобы нельзя было:
   - создать две ставки одного игрока параллельными запросами;
   - забрать выигрыш уже после краша из‑за гонки с driver-loop.
2. **Откат кэшаута при ошибке БД** — если `addBalance` упал, флаги `cashedOutMult` / `payout` сбрасываются, повтор возможен.
3. **Авто-кэшаут не роняет тик** — ошибка одной выплаты не блокирует краш раунда.
4. **Vite proxy WebSocket** — `ws: true` для `/api`, иначе локально сокет не апгрейдится.
5. **Корректный `resolveWsUrl`** — `https` → `wss` через `URL`, а не хрупкий `replace`.
6. **UI множителя** — клиент не «перелетает» краш/кэшаут: `Math.min` с `crashMultiplier` и своим `cashedOutMult`.

## 4. Какие проблемы были исправлены

### Критические (Aviator)

1. Гонка **кэшаут vs краш** — выплата могла пройти уже после crash.
2. Гонка **параллельных ставок** — риск двух записей одного `userId` или превышения лимита.
3. **Потеря выплаты** при падении `addBalance` после установки флага «уже забрал».
4. Локальный **WebSocket** через Vite без `ws: true`.

### Важные (UI / клиент)

5. Кратковременный **овершут множителя** на клиенте после краша/кэшаута.
6. Хрупкое построение `wss://` URL.

### Ранее (экономика продукта)

7. Race condition баланса «read → modify → write».
8. Двойная трата купонов из‑за суммирования истории.
9. Слабая защита от спама API.
10. `Math.random` в призах / house edge.

### Известные ограничения (не баги, но важно)

- Состояние раунда Aviator **в памяти одного инстанса** Railway — при горизонтальном масштабе раунды разъедутся.
- При рестарте сервера ставки в полёте считаются проигранными (уже списаны) — осознанно.
- Демо не меняет баланс-снимок — осознанно.
